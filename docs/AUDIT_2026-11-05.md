# Audit du dépôt Robot (ROSOrin Pro) — 5 novembre 2026

Objectif visé : donner des ordres au robot à la voix (micro du robot ou micro du PC) ou depuis une page Web, et qu'il les exécute seul en utilisant tous ses capteurs (lidar, caméra RGB, profondeur, IMU, odométrie) et son bras.

Périmètre lu : dépôt GitHub `5nvn9z8jk7-sketch/Robot`, branche `main` (commit `060a264`), 182 fichiers, plus la PR #3 ouverte et les notes des sessions du 30/10 au 02/11. Le robot lui-même n'a pas pu être interrogé pendant l'audit : tout ce qui concerne l'état réel sur la Jetson est marqué « à vérifier ».

---

## 1. Synthèse en 6 points

1. **Les briques de base marchent** : saisie du cube rouge (v6 calibrée par démonstration), détection couleur ~10 Hz, superviseur caméra, watchdog, keypad Web, ASR/TTS français hors ligne, Ollama sur le PC.
2. **Il n'y a pas de « cerveau » unique.** Quatre nœuds (`llm_move_bridge`, `autonomous_mission_node`, `pick_and_place_node_v6`, `agent_process` Hiwonder) écoutent tous le même texte `/vocal_detect/asr_result` et décident chacun par mots-clés. Plusieurs nœuds publient `/controller/cmd_vel` en même temps, sans arbitrage.
3. **Il n'y a pas d'arrêt d'urgence global.** ESPACE/0 sur la page Web envoie une seule commande vitesse nulle; une mission ou une saisie en cours continue de publier. Le correctif du pick v6 est dans la PR #3, jamais testée ni fusionnée.
4. **Le lidar, la profondeur et la navigation (SLAM/Nav2) ne sont pas utilisés** par vos nœuds. Le lidar est abonné dans la mission mais jamais lu; « évitement d'obstacles » et « mesure de distance par profondeur ±2 cm » décrits dans `GUIDE_AUTONOME_COMPLET.md` n'existent pas dans le code actuel. Or le ROSOrin Pro est livré pour la cartographie SLAM, la planification de trajet et l'évitement dynamique ([fiche Hiwonder](https://www.hiwonder.com/products/rosorin-pro)), avec Cartographer/Gmapping/Hector et une planification locale TEB ([blog Hiwonder](https://www.hiwonder.com/blogs/news/rosorin-pro-ros)), documentés dans les chapitres « Mapping & Navigation » et « Large AI Model » du [wiki ROSOrin Pro](https://wiki.hiwonder.com/projects/rosorin-pro/en/latest/).
5. **Trois chemins micro PC concurrents** (reconnaissance du navigateur → port 9090, page locale → port 9091, script Python → port 9092) et deux nœuds ASR serveur quasi identiques.
6. **Le dépôt est difficile à maintenir** : 70 scripts `.sh`, 41 `.py` dont 7 versions du pick, 8 fichiers `.log`, 13 fichiers d'état/guide à la racine, 46 fichiers avec IP en dur (`192.168.1.30` / `.20`), scripts de lancement qui démarrent encore l'ancien pick v1. Les tests GitHub Actions ne testent que la simulation `toy_sorter`, pas le code réellement déployé.

### Mineur — maintenance

- 7 versions du pick (`pick_and_place_node.py`, v2…v6, v5_diag), 3 versions de la détection couleur, 2 watchdogs caméra `.sh` obsolètes, `robot_keypad.html.bak`, 8 `monitor_*.log` versionnés. La PR #3 range déjà ceci dans `archive/`.
- IP en dur dans 46 fichiers; Tailscale (`ubuntu-desktop`) n'est utilisé nulle part dans le code.
- Les nœuds sont des scripts lancés par `setsid nohup` + `pkill -f`, pas un paquet ROS 2 avec fichier de lancement : pas de `ros2 launch` unique, pas de paramètres YAML, d'où les pièges `pkill` qui se tuent lui-même et `bash -lc`.
- Le paquet `toy_sorter` (FSM, perception, navigation, manipulation) a de bonnes interfaces mais ses 3 `ros2_backend.py` sont des squelettes (pseudo-code); il n'est relié à rien de ce qui tourne.
- La CI vérifie la syntaxe et la simulation, mais aucun test ne couvre l'analyse des phrases, l'arrêt, ou la logique mission.
- Commit `88889c2` noté « non poussé » le 01/11 : il est bien sur GitHub aujourd'hui (OK).

## 3. Architecture cible

```
 ENTRÉES (3 sources, 1 seul format)
 ┌──────────────┐ ┌──────────────────┐ ┌───────────────────────────┐
 │ Micro robot  │ │ Micro PC         │ │ Page Web (servie PAR le   │
 │ WonderEcho   │ │ (dans la page    │ │ robot) : boutons, zone de │
 │ Pro → ASR fr │ │  Web, push-to-   │ │ texte, gros bouton STOP   │
 └──────┬───────┘ │  talk) → ASR fr  │ └─────────────┬─────────────┘
        │         └────────┬─────────┘               │
        └──────────────────┼─────────────────────────┘
                           ▼
             /robot/command  {texte, source, horodatage}
                           │
                ┌──────────▼──────────┐
                │  ROUTEUR D'ORDRES   │  1) « stop » → /robot/estop immédiat
                │  (un seul nœud)     │  2) grammaire fixe (avance 1 m,
                │                     │     tourne 90°, attrape, dépose…)
                │                     │  3) sinon LLM Ollama → plan JSON
                │                     │     limité à la liste des compétences
                └──────────┬──────────┘
                           ▼
                ┌─────────────────────┐   un plan = suite de compétences
                │ EXÉCUTEUR DE TÂCHES │   (arbre de comportement ou FSM),
                │ (mission manager)   │   annulable, avec retour d'état
                └──┬───┬───┬───┬───┬──┘
                   ▼   ▼   ▼   ▼   ▼     COMPÉTENCES = actions ROS 2
   drive / rotate  navigate_to  find_object  pick   place_in_bin  look/describe
   (odom + IMU)    (Nav2 +      (couleur ou  (v6)   (bac 23 cm)   (VLM, option)
                   carte SLAM)  YOLO + prof.)
                           │
                ┌──────────▼──────────┐
                │ SÉCURITÉ            │  twist_mux (estop > manuel > auto)
                │                     │  collision_monitor lidar, batterie,
                │                     │  vitesse max, délai sans commande
                └──────────┬──────────┘
                           ▼
                  /controller/cmd_vel  →  moteurs
   RETOUR : /robot/status (état, tâche, batterie, erreur) → page Web + voix
```

Principes :

- **Une seule porte d'entrée** (`/robot/command`) et **un seul décideur**. Les nœuds pick, mission, bridge n'écoutent plus l'ASR : ils deviennent des compétences appelées par l'exécuteur.
- **Chemin rapide sans LLM** pour les ordres simples et l'arrêt (réponse < 0,5 s, fonctionne même si le PC est éteint). Le LLM ne sert qu'aux phrases libres (« range les cubes rouges dans le bac puis reviens ici ») et ne peut produire que des appels de compétences connues, validés avant exécution.
- **Chaque compétence est une action ROS 2** : objectif, retour de progression, résultat succès/échec, annulation. C'est ce qui permet les vrais « 3 essais », l'arrêt propre et l'enchaînement.
- **Le robot sert lui-même la page Web** (rosbridge déjà présent) → accessible depuis n'importe quel PC/téléphone, via le réseau local ou Tailscale, sans IP en dur.

## 4. Plan de travail proposé (par lots testables)

Chaque lot se termine par un essai physique court sur le robot avant de passer au suivant.

### Lot 0 — Remise en ordre (½ journée)
- Fusionner la PR #3 après ses 4 essais (arrêt pendant pick, rotation odométrie, déclencheurs, scripts).
- Archiver les anciennes versions, supprimer `.log`/`.bak`, réécrire `README.md` et un seul `ETAT_PROJET.md` à jour; fichier `config/robot.yaml` (hôte robot, hôte Ollama, vitesses) lu par tous.
- Supprimer le bloc « relance moteurs » de `start_interface.bat`.
- **Test** : redémarrage du robot → tous les nœuds attendus présents, un seul pick (v6).

### Lot 1 — Sécurité commune (1 jour)
- `/robot/estop` + `twist_mux` + `collision_monitor` sur le lidar.
- Tous les nœuds respectent l'arrêt en < 200 ms; la page Web a un bouton STOP permanent + ESPACE.
- **Test** : arrêt pendant pick, pendant mission, pendant joystick; obstacle (carton) devant en marche avant → arrêt automatique.

### Lot 2 — Routeur d'ordres unique (1–2 jours)
- Normalisation du texte (accents, ponctuation, nombres en lettres « un, deux, dix, cinquante centimètres, quatre-vingt-dix degrés »).
- Grammaire fixe : avance/recule/décale à gauche-droite (mecanum) X m ou cm, tourne X degrés, stop, attrape le cube [couleur], dépose dans le bac, va à [lieu], retourne à la base, état/batterie.
- Repli LLM (Ollama) avec sortie JSON stricte limitée aux compétences, refus si invalide, confirmation vocale avant les actions longues.
- Tests unitaires sur ~50 phrases réelles (ajoutés à la CI).
- **Test** : la même phrase donne le même résultat depuis le micro robot, le micro PC et la zone de texte.

### Lot 3 — Compétences fiables (2–4 jours)
- `drive` / `rotate` en boucle fermée odométrie + IMU (code déjà présent dans pick v6 et PR #3), utilisés partout.
- `pick` = pick v6 transformé en action (succès vérifié : cube visible dans la pince / plus visible au sol).
- `place_in_bin` : bac blanc fixe 23 cm, bras levé au-dessus, ouverture pince (séquence commencée le 02/11, non validée).
- `find_object` : couleur + **profondeur** (distance réelle du cube) au lieu de la seule taille en pixels; option YOLO plus tard (dossier `training/` existant).
- Mission « attrape tous les cubes » réécrite comme plan : chercher → attraper → aller au bac → déposer → recommencer.
- **Test** : 10 cycles complets, taux de réussite noté.

### Lot 4 — Navigation avec carte (2–3 jours)
- Créer une carte de la pièce avec le SLAM Hiwonder, sauvegarder des lieux nommés (« base », « bac », « cuisine »…).
- Compétence `navigate_to` via Nav2 (évitement dynamique par lidar + profondeur).
- « Retourne à la base » devient une vraie navigation; retour automatique si batterie faible.
- Prérequis signalé le 02/11 : IMU (accélération au repos ≈ 9,38 m/s² au lieu de 9,81, correcteur non intégré au démarrage) à finaliser pour une odométrie fusionnée fiable.

### Lot 5 — Interface Web unifiée (1–2 jours)
- Une seule page, servie par le robot : flux caméra, carte avec position, état de la tâche, batterie, journal, zone de texte, bouton micro (push-to-talk, ASR sur le robot), boutons d'ordres prédéfinis, STOP.
- Remplace `robot_keypad.html`, `pc_voice_control.html`, `pc_voice_control_local.html`.
- Un seul serveur audio WebSocket (fusion de `pc_audio_asr_server.py` et `ws_audio_asr_node.py`), avec VAD Silero au lieu du seuil d'énergie fixe.

### Lot 6 — Options avancées
- Mot de réveil « robot » sur le micro du robot (pour ne pas réagir aux conversations).
- Modèle vision-langage (VLM) pour « qu'est-ce que tu vois ? » / « trouve la balle bleue » — supporté par le firmware Hiwonder selon la [fiche produit](https://www.hiwonder.com/products/rosorin?variant=41983145574487).
- Paquet ROS 2 propre (`robot_brain`) avec un `ros2 launch` unique remplaçant les `setsid nohup`.
